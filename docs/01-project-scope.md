# 第一阶段：项目范围

## 1. 项目名称

中文名：具身智能产业关系图谱  
英文名：EmbodiedGraph  
研究副标题：以宇树科技为中心的供应链、资本与合作生态研究

## 2. 产品目标

为产业研究人员、投资研究人员和业务决策者提供一个关系研究入口，使其能够快速查看宇树科技相关实体，并追溯每条关系背后的证据、时间和判断过程。

首版重点验证三件事：

1. 分散的公开资料能否被整理为统一的关系结构。
2. 事实、推断和未知能否在同一产品中被清楚地区分。
3. 评审者能否从任意结论快速返回原始证据。

## 3. 核心用户

### 主要用户

- 需要快速理解具身智能产业关系的研究人员。
- 需要核查公司合作、供应链或资本关系的投资与战略人员。
- 需要评估研究结论可靠性的审核者。

### 首版不重点服务

- 需要实时交易信号的投资者。
- 需要完整采购价格、产量或合同金额的供应链管理人员。
- 需要个人联系方式或销售线索的商业拓展人员。

## 4. 核心使用场景

1. 查看宇树科技已公开确认的供应链与合作关系。
2. 按关系类型、时间、状态和置信度筛选实体。
3. 打开一条关系，阅读结论、证据定位和评分解释。
4. 查看某条关系是否已经过期、存在冲突或仍待验证。
5. 通过 API 或命令行复用固定数据快照。

## 5. 研究问题

### 供应链

- 哪些企业被公开材料直接确认向宇树提供产品、技术或制造服务？
- 哪些零部件只能确认出现在产品中，但不能确认存在直接采购关系？
- 是否存在单一来源依赖或关键信息缺口？

### 客户与应用

- 哪些机构被公开确认采购、部署或使用宇树产品？
- 展示、试用、联合实验和正式采购如何区分？
- 客户关系在什么时间范围内有效？

### 合作生态

- 宇树与高校、科研机构、开发平台和渠道机构有哪些公开合作？
- 合作是联合研发、生态兼容、渠道销售还是一次性活动？

### 资本关系

- 哪些投资方在什么轮次进入？
- 投资关系的来源和时间是否能被交叉验证？
- 当前持股关系无法确认时，应如何表达历史融资事实？

### 竞争关系

- 哪些企业在产品形态、目标客户或技术路径上构成直接竞争？
- `peer` 是基于公开市场定位还是研究者推断？

## 6. 范围边界

### 纳入

- 无需登录即可访问的公开网页和文件。
- 公司官网、监管披露、政府、高校和合作方的公开信息。
- 权威媒体和行业资料中可定位、可复核的内容。
- 有明确发布日期或可合理确定时间范围的证据。

### 不纳入

- 登录后内容、付费墙内容和绕过访问限制获得的数据。
- 个人隐私、联系方式、客户机密和非公开合同。
- 无法定位原始出处的转载、营销号和匿名爆料。
- 仅凭产品拆解就断言存在直接供应合同。
- 仅凭同场参展、社交媒体互动或图片同框就断言合作关系。

## 7. 首版规模

- 实体数量：约 20-30 个。
- 关系数量：15-20 条高质量关系。
- 每条关系至少 1 个可访问来源。
- 重要关系优先争取 2 个相互独立的来源。
- 五类关系均建立查询入口，但不强制每类达到相同数量。

## 8. 成功标准

首版成功不是“找齐宇树供应商”，而是做到：

- 评审者能理解每条关系为何成立。
- 任何推断都不会伪装成事实。
- 关键结论可在两次点击内返回原始来源。
- 数据快照能够离线复现主要查询结果。
- 研究限制和未知信息被明确呈现。

## 9. 关键风险

| 风险 | 处理方式 |
| --- | --- |
| 宇树公开供应链信息较少 | 降低数量目标，保留未知状态，不虚构供应商 |
| 新闻转载形成伪多源验证 | 识别共同原始出处，转载不计为独立证据 |
| 历史融资信息与当前股权混淆 | 分开记录事件事实与当前状态 |
| 产品使用不等于客户关系 | 区分采购、部署、试用、展示和合作实验 |
| AI 摘要产生关系误判 | 所有关系必须人工打开来源复核 |

## 10. 第一阶段退出条件

满足以下条件后进入第二阶段：

- 项目定位、核心用户和研究问题已经确定。
- 五类关系的定义和边界已经确定。
- 研究时间截点和首版规模已经确定。
- 测试题要求已经转换为可检查的验收项。
- 已明确资料不足时允许呈现未知，不以猜测补齐数据。
